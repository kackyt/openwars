# CONSTRAINTS.md - プロジェクト制約事項

## 1. 技術的制約

### プラットフォーム制約
- **対応OS**: Windows, macOS, Linux (CLIおよびTauri GUIが動作する環境)
- **モバイル対応**: N/A (デスクトップ主体)

### 開発環境制約
- **プログラミング言語**: Rust (edition 2024)
- **主要フレームワーク**:
  - `engine`: `bevy_ecs` (0.15.2)
  - `cli`: `ratatui` (0.26), `crossterm` (0.27)
  - `gui`: Tauri (予定)
- **データフォーマット**: JSON, CSV等によるマスターデータ管理

### インフラ制約
- **ホスティング環境**: N/A (ローカル実行アプリケーション)
- **ストレージ容量**: セーブデータやマスターデータ用のローカルディスク数MB程度

## 2. ビジネス制約

### 予算制約
- **開発予算**: オープンソースプロジェクトのためN/A

### 時間制約
- **プロジェクト期限**: 継続的開発（OpenSpec駆動）

### リソース制約
- **開発チーム**: 少数精鋭のコントリビューターおよびAIエージェントによるペアプログラミング

## 3. 法的・規制制約

### コンプライアンス要件
- N/A

### ライセンス制約
- **使用可能ライセンス**: MIT, Apache 2.0 等のOSS互換ライセンス

## 4. 組織的制約

### 承認プロセス
- OpenSpecの仕様変更（`spec.md`, `proposal.md`）とそれに準拠するコードのレビュープロセスを通じた承認
- AIによる`code-review`スキルを用いた敵対的レビューの実施

### 既存システムとの統合
- N/A

## 5. 品質制約

### パフォーマンス基準
- **レスポンスタイム**: CLI上の入力に対してストレスなくゲーム進行・描画更新が行われること。特にターミナル上での描画は1フレーム遅延を考慮した状態遷移を行うこと。
- **メモリ制約**: メモリのライフサイクルを意識し、無駄なコピーやclone、解放タイミングが不明なBoxを避ける。

### 信頼性基準
- **状態の安全性**: ターンやフェーズの遷移において不正なゲーム状態に陥らないこと。（例：戦闘、占領、生産などのドメインロジックの非漏出）

### セキュリティ基準
- **特記事項**: ローカルゲームアプリとしての一般的なセキュリティ（不正なセーブデータによるクラッシュ防止など）を確保する。

## 6. 外部依存関係

### サードパーティライブラリ

| ライブラリ名 | 用途 | 制約事項 |
| --- | --- | --- |
| `bevy_ecs` | エンティティとコンポーネント管理 | バージョンアップ時の破壊的変更に注意 |
| `ratatui` | CLI UI描画 | ターミナルの制約を受ける |
| `thiserror` / `anyhow` | エラーハンドリング | アプリケーション層とドメイン層での使い分け |

## 7. 制約の優先順位

### クリティカル（変更不可）
1. ドメインロジックの非漏出（ゲームルールをUIクレートに記述しない）
2. 値オブジェクト（Newtypeパターン）を用いた型安全な実装
3. 依存性の注入（DI）を用いたインターフェース分離

### 重要（変更には承認必要）
1. `bevy_ecs`のバージョン等、基盤ライブラリの大幅な変更
2. OpenSpecに記載された仕様（ルール）の変更

### 推奨（ガイドライン）
1. 静的ディスパッチ（ジェネリクス）の優先利用（パフォーマンス重視）
2. 日本語のコメント付与
