## 制圧ロジックが欠けている箇所

地域の状態観測、占領担当、移動目標は存在する。しかし、`tactics/v2.rs` は各部隊の最良候補を独立に採点して比較する。DAGの地域状態と目標座標を渡しても、「撃破に必要な砲撃を同じ障害へ集約する→進入役の行動を残す→排除を観測してそのセルへ進入する」という協同行動にはならない。`capital_route/node_operation.rs` の状態遷移は観測であり、この行動列を実行しない。砲台フェリーの先行射撃も自走砲を含む火力の集約・進入予約を実行しない。

試作のmap_20先手T20では、(20,8)の敵歩兵（HP64）に、step 4の歩兵が12、step 5の重歩兵が17、step 6の重自走砲が35ダメージを与えて排除した。直接部隊は既に行動済みである。自走砲の順番だけを先にしても、その一発では撃破に足りない。必要な火力を組み合わせ、別の進入役の行動を残す計画が必要となる。単なる射程・unlock条件の緩和では解消しない。

## 設計の達成条件

- 地域へ配属した小隊数ではなく、実到達・敵の排除・占領・後続の前進で地域制圧を判定する。
- 首都は最終目的地であり、当面の地域制圧・占領対象とは分ける。首都だけへ全軍を集めない。
- 敵首都の生産可能範囲3マスへ実際に進入し、範囲内の敵工場の占位または占領を確認する。一時占位と、敵手番を越えた維持を分ける。
- 砲撃後に戦車・歩兵が前進し、後続も攻撃を続けることを確認する。攻撃中の損失自体を失敗条件にはしない。

## 単体検証

上記の最終試作について全1175件が成功した。以下は個々の接続を検査した内容であり、実戦での制圧達成を保証しなかった。

主な振る舞いのテスト:

- 通常V4が確定済みの地域指示を使う。生産口退避でも各部隊の指示方向へ実際に動く。
- 通常戦術前の実砲台フェリー経路で、地域内の低価格敵を地域外の高価格敵より先に撃ち、地域内の敵が射程外へ移ればLoadする。地域内の敵が消えれば地域外への射撃を再開する。
- 味方が一つの進入口を占めれば別の入口を使い、占領役は異なる施設を選ぶ。
- 敵のスクリーンがあっても前方の目標を失わない。
- 戦車・重歩兵・自走砲が射程内の手前で止まらず、指定した空き地域へ入る。
- 地域外からの射撃と、敵除去後の地域への前進を実際の戦術コマンドで確認する。
- 同時に撃てる高価な別地域の敵がいても、現在地域の障害を先に攻撃する。障害を除いた後は別地域の有利な攻撃も許し、指定座標だけへの硬直した攻撃制約にしない。
- 防衛から前進Controlへ再指令された部隊は必要な不利交換を選び、Holdの守備隊は選ばない。
- 各回廊の入口へ出発点から到達でき、入口から首都へ進める。DAGは循環しない。
- 首都を終点に保ちながら、手前の未制圧地域を現在の区間として処理する。砲兵の射撃位置が後方でも、明示所属の方面と首都という目的を失わない。
- 一方の方面が首都へ進んでも、他方の地域制圧指示は残る。
- 首都の代表点以外への実到達を観測し、前衛を後方へ呼び戻さない。輸送中は到達と数えない。
- Controlの橋で先遣歩兵・戦車と複数の間接火力がともにAdvanceとなる。間接火力は通過枠を消費しない。さらに側方の遠方部隊より、出口に早く着く歩兵へ前衛枠を渡す。旧来の自首都距離順では逆転するケースを検証する。
- 橋の通過役がいる間、砲兵の完了条件は射程内の支援、戦車の完了条件は出口の実占位となる。通過役を失っても砲兵が自ら渡れる。
- 攻勢作戦の砲兵はAttackを維持し、防衛への明示変更ではDefenseになる。
- 砲台が地域の敵を撃つために実際にLoadを選ぶ。配送先はキャッシュ中の更新と搭載後にも保持される。
- 損耗で初回Go条件が成立しなくなった状態でも、開始済みの攻勢を継続する。明示的な防衛変更は妨げない。
- 防衛必要量0・1部隊分の双方で、所要分だけを残し、余剰と新規部隊を遠方の攻勢へ送る。充足済み防衛への再吸収、二重配属、部隊の消失がない。

## 対戦の判定方法

V4対V200、Hex、seed 1。map_20は両手番、map_47は先手のみ。自手番の前後盤面、攻撃・生産・占領イベント、地域指示、待機プローブを保存する。

「最終目的地が首都」という欄だけでは、首都への前進指示とは数えない。`phase == Advance` と最終目的地を合わせて数え、さらに実行地域も首都地域になった指示を別に数える。地上部隊の敵首都からのHex距離、生産範囲への進入、初期敵工場の占位・占領を実盤面で検査する。

地域状態には計画時点の観測が残る一方、診断のユニット座標は手番末に更新される。手番末の兵力を使って計画時点のContested等を誤判定と断定しない。実際に次手番も停止するか、同じ時点を作った単体テストで旧条件を検査する。
