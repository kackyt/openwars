# 前線都市の不当減点解消と接近スコア連続化による前進・合流改善計画

## Context
プローブによる実測と分析により、以下の2つの根本問題が特定された：
1. **前線都市への -20,000点 減点バグ（渋滞の最大要因）**:
   - ゲームルール上、生産可能な自軍施設は「自軍首都から3マス以内（square/hexトポロジー準拠）」に限られる（`engine/src/systems/production.rs:18`）。
   - しかしAIの待機評価（`scoring.rs::repair_site_at`）では距離を考慮せず全自軍施設を `is_production_facility` で判定していたため、首都から遠く離れた前線の占領済み都市・工場を「生産枠封鎖」と誤認し、通過・待機に `-20,000点` の莫大なペナルティを課していた。
   - これにより、中央の前線都市群が「進めない壁」となり、先頭車両が停止して後続が40体以上スタックする大規模な渋滞を引き起こしていた。
2. **接近点不変（相殺）バグ**:
   - `approach_bonus` は `TurnDistance` の `turns`（`div_ceil` で切り上げられた整数）しか受け取っていない。
   - 目標へ2マス前進しても、途中の迂回コスト（山岳・森）で `used_mp` がわずか1増えてターン数切り上げ境界（例: 48 MP → 49 MP で 12ターン → 13ターン）を跨ぐと、ターン減点（-1,000点）が発生する。
   - 一方、格子距離短縮による加点は軽戦車（移動力4）で 2マス短縮時 +1,000点であり、ターン減点（-1,000点）と完全に相殺（0点差）していた。
   - その結果、現在地（森: 防御+200点）と前進先（道路: 防御+0点）の地形防御点差（200点差）だけで「動かずに森に留まる方が200点高い」と判定され、ユニットが目標へ前進できなくなっていた。また、Square前提の `manhattan` 距離決め打ちにより Hex トポロジーとの不整合も生じていた。

本計画ではこの2つの原因を解消し、前線都市の通過と目標への前進を正常化させ、部隊の集合・合流・連携を成立させる。

## 1. 修正内容

### A. 生産施設判定の首都圏限定化 (`engine/src/ai/tactics/board.rs`, `scoring.rs`)
- **自軍首都位置の取得**:
  - `TacticalBoard` に `pub(crate) fn own_capitals(&self) -> Vec<GridPosition>` を追加。
  - `board.properties` から `terrain == Terrain::Capital && owner == Some(self.player_id)` を抽出。
- **`repair_site_at` の生産拠点判定の厳格化**:
  - `board.registry.is_production_facility(terrain)` に加え、`crate::systems::production::is_within_production_range(&capitals, pos.x, pos.y, board.map.topology)` を満たす場合のみ `Some(true)`（生産施設、回復不要時 -20,000点）を返す。
  - 首都から3マス超の前線都市・工場は `Some(false)`（一般回復拠点、回復不要時 -2,000点）となる。
  - これにより、前線都市を通る前進が `-20,000点` で理不尽にブロックされるバグを根絶する。

### B. 接近スコアの連続ターン化とトポロジー対応 (`engine/src/ai/tactics/approach.rs`, `scoring.rs`)
- **トポロジー対応距離の提供**:
  - `ApproachDistances` に `pub(crate) fn distance(&self, a: GridPosition, b: GridPosition) -> i32` を追加し、`self.board.map.distance(a.x, a.y, b.x, b.y) as i32` を呼ぶ（Square / Hex 両対応）。
  - `scoring.rs` 内の `manhattan` 呼び出し（`squad_target_approach_score`, `reference_point_approach_score`, `solo_hunt_score`）を `distances.distance` に置換。
- **`approach_bonus` の連続値化**:
  - シグネチャを `approach_bonus(dist: TurnDistance, grid_distance: i32, max_movement: u32) -> i32` に更新。
  - 到達可能時（`dist.turns < UNREACHABLE_TURNS`）は、整数 `turns` ではなく `cont_turns = dist.used_mp as f32 / max_movement.max(1) as f32` を使用：
    ```rust
    let turn_score = (100.0 - cont_turns).max(0.0) * 1000.0;
    let moves = grid_distance as f32 / max_movement.max(1) as f32;
    let move_score = (100.0 - moves).max(0.0) * 2000.0;
    (turn_score + move_score) as i32
    ```
  - 目標・射程到達時（`used_mp = 0, grid_distance = 0`）は従来どおり **300,000点満点** を維持し、既存の契約・テストを保護。
  - コストがわずか1増えても減点は -250点（軽戦車の場合）にとどまり、格子距離短縮（2マスで +1,000点）が確実に上回るため、差引 +750点の加点となり、森の地形防御点（+200点）に負けず前進が選ばれる。

### 残課題
- `consider_wait`（`tactics/v2.rs`・`tactics/small_map.rs`）は campaign 所属unitの後退を格子距離で判定するため、山を迂回する前進を候補から外している（map_6 の1局で `wait_move_away_from_campaign` 却下 14,133件）。経路長での判定に置き換える。
- 敵ユニットが目標への入口を塞ぐと `calculate_turn_distance` が近似値（`50 + マンハッタン/4`）へ落ち、評価が直線距離に退化する。敵マスを高コストで通過可能とみなした距離で代替する。

## (a) 待機の後退判定を経路長に置換（2026-10-20）

`consider_wait`（`tactics/v2.rs`・`tactics/small_map.rs`）の「campaign目標から遠ざかる待機」を、格子距離ではなく**地形だけで測った経路長**（占有を無視した逆Dijkstraの消費移動力）で比較するよう変更した。判定は `ApproachDistances::target_progress` / `TargetProgress::moves_away`（`tactics/approach.rs`）に集約し、地形のみの距離cacheを `ActionDistanceCache` に追加して手番内で共有する。

- 敵ユニットを壁とみなす距離（接近点と同じもの）で比べると、前線の敵を大回りする経路が最短になり、後退が前進扱いになった（golden `v4_small_map1` T4 で、歩兵が (4,7) の占領をやめて (3,9) へ後退）。後退判定は地形の迂回を許すためのものなので、占有は無視する。
- 現在位置から地形的に到達不能なら従来の格子距離判定にフォールバック、移動先だけが到達不能なら後退扱い。
- 経路長が等しい横移動は許可（従来も格子距離が等しい移動は許可していた）。
- golden は全件不変。回帰テスト `v2/detour_tests.rs`（山の壁を回り込む前進が待機候補に残る）と `TargetProgress` の単体テストを追加。

| 変種 | map_6 撃破勝ち（8局） | map_6 T31-40 / T41-50 敵首都までの平均距離 | 首都3マス以内率 T41-50 | 回帰セット V4 勝利（20局） |
| --- | ---: | ---: | ---: | ---: |
| A のみ（基準） | 2 | 16.2 / 15.0 | 1.7% | 16 |
| A ＋ (a) | 1 | 15.4 / 14.2 | 3.3% | 16 |

- 待機マスの防御と隣接平均との差は −3.35 → −3.23 でほぼ不変（地形課題は残る）。

## (b) 敵に塞がれた目標への接近距離を「押し通る距離」で代替（2026-10-20）

`ApproachDistances::turns`（接近点の計算）だけを対象に、通常の距離が到達不能（敵が入口を塞ぐ）なら、敵占有マスを1ターン分（`max_mp`）の追加costで通過可能とみなした逆Dijkstra（`calculate_turn_distance_through_enemies`、`ai/turn_distance.rs`）で代替する。従来は `50 + マンハッタン/4` の近似値に落ち、地形を無視した評価に退化していた。押し通る距離は敵配置に依存するため、専用cacheを `ActionDistanceCache` に持たせ、敵配置が変わったら通常の距離cacheと同時に破棄する。他の28か所の `calculate_turn_distance` 呼び出しは変更しない。golden は不変。

| 変種 | map_6 撃破勝ち（8局） | map_6 T31-40 / T41-50 敵首都までの平均距離 | 回帰セット V4 勝利（20局） | map_6 最終盤面で首都への経路が敵に遮断されたunit |
| --- | ---: | ---: | ---: | ---: |
| A ＋ (a) | 1 | 15.4 / 14.2 | 16 | seed7 で 100体 |
| A ＋ (a) ＋ (b) | 1 | 16.0 / 13.9 | 17 | 0 |

- 回帰の差分: map_32 V4後手 seed2・map_42 V4後手 seed1 が勝ちに、map_42 V4後手 seed2 が負けに。
- 最終盤面では全局で首都へ到達可能になったが、撃破勝ちは増えていない。首都隣接の空きマスは1〜6で、首都手前の渋滞（残課題3）が次の律速と考えられる。

## 待機に陥る原因の分析（2026-10-20）

`fix/wait-scoring`（(2) 採用後）で map_6 seed1 を待機プローブ付き（P2、T5〜50）で1局実行し、発行された通常戦術のWait 2,939件を分類した。目標切替の集計は同じバイナリの seed1〜8 でも行った。

### Waitの内訳（T20〜50、2,500件）

| 分類 | 件数 | 割合 |
| --- | ---: | ---: |
| 目標へ前進して移動を終えた | 1,634 | 65% |

- 攻撃が優先度・作戦制約で却下されたWaitはほぼ0件で、待機したunitの射程には敵がいない。出発許可待ち（holds_position）もT20以降は0件。
- 待機の大半は「目標へ向かって移動中」であり、問題は移動先（割り当て）にある。T50時点でV4は160体、敵は12体だが、敵から3マス以内にいるV4は9体だけ。

### 割り当ての構造（原因）

1. **本土全体が1つのcampaignで、目標が常に1か所。** 両首都が同じ陸塊にあるため island 0 のcampaignだけが存在し、占領役40〜60体と戦闘役30〜90体のすべてが1つの `target_position` を中心に動く（`island_campaign_history`）。
2. **目標を軍の位置ではなく自軍物件網から選ぶ。** `target_selection.rs::capture_front_origins` は、同一陸塊の首都戦役では起点を自軍所有物件の全体にする。次の目標は「どこかの自軍物件に最も近い未所有物件」となり、南で占領を終えた軍が北の物件へ向き直る。seed1 では T38〜43 に (7,6) → (6,2) へ北上し（軍の平均位置から最寄りの未所有物件 (11,11) より3〜5マス遠い）、T44 に (9,14) へ南下した。seed1〜8 では T20〜50 に目標が9〜17回切り替わり、うち4〜10回は5マス以上の移動。割り当てられたunitは目標から常に平均約10マスの位置にいて、到着する前に次の目標へ切り替わる。
3. **余った占領役を、既存の担当を見ずに最寄り物件へ送る。** `squad.rs::campaign_assignment_capture_responsibilities` は前線帯の各物件へ最寄りの1体を割り当てた後、残りを1体ずつ「自分に最も近い未所有物件」へ送る。本国から流れてくる歩兵は同じ物件を選ぶため、占領任務のWaitの対象物件には平均25体の占領役がいて、58%は自分より近い占領役が5体以上いた（T47 では48個の占領Squadが (10,14) 1か所へ向かう）。
4. **余った戦闘役も最寄りの前進目標へ1つの防衛Squadとしてまとめる。** `objective_allocation.rs` で脅威への攻撃に割り当てられなかった戦闘役は `campaign_advance_responsibilities` で各自の最寄り目標へDefense任務として送られ、48〜59体のSquadが1物件へ集まる（T41〜50 のWaitのうちAttack任務は毎ターン5〜16体、Defense任務は46〜61体）。
5. **増援の供給線が長く、生産が止まらない。** 首都間距離27マスで、生産は自軍首都から3マス以内だけ。V4の24〜50%が常に自軍首都から8マス以内にいる。首都攻略作戦の占領枠は充足が数えられず占領用の歩兵を買い足し続ける（前節）。この修正だけでは戦闘枠の歩兵が増えるだけだったのは、増えた歩兵も 3・4 の同じ集中先へ流れるため。

### 改善の方向（未実装）
- 目標選択の起点を、同一陸塊の首都戦役でも自軍物件網ではなく割り当て済みunitの位置（前線）にし、切替に到着ベースのヒステリシスを持たせる。
- 余った占領役は既存の担当数を考慮して前線帯の複数物件へ上限つきで配り、残りは軍に追随させる。
- 余った戦闘役を1物件の防衛Squadへまとめず、複数の前進目標や敵首都・敵unitへのAttackに分ける。
- 占領枠の充足判定と戦闘計画の歩兵購入を合わせて見直し、供給線が長いときの買い足しを抑える。
