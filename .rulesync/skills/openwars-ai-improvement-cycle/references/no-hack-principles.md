# 評価値ハック排除原則（No-Hack Principles）

本ドキュメントは、OpenWars AI開発における「評価値ハック（根拠なき定数・場当たり的なスコア調整）」を排除し、健全で保守可能な戦術評価関数を維持するための設計基準です。

---

## 1. 評価値ハックの定義と禁止事項

### 1.1 根拠なき生リテラル（マジックナンバー）の禁止
- **禁止パターン**:
  - `score += 3000;`、`base_tile_score -= 10_000;` のように、理由・較正根拠のない数値を直接加減算する。
  - 同じ「物件を塞ぐ」理由に対して、箇所ごとに `-3000`, `-10_000`, `-20_000` と異なる数値を場当たり的に割り当てる。
- **正当な設計**:
  - 評価値は名前付き定数とし、コメントに**選定理由・較正の考え方**を明記する。
  - 例: `const UNOWNED_PROPERTY_BLOCK_PENALTY: i32 = 10_000; // 歩兵の占領完了価値（約+5000）を確実に上回り、即時退去を強制する基準`

### 1.2 特定マップ・局所シチュエーション向けアドホック分岐の禁止
- **禁止パターン**:
  - `if map_name == "map_32"` や「自陣工場が7つの時だけこの兵種を除外する」といったマップ名・特定初期配置への特化。
  - 兵種名をハードコードして「歩兵は占領対象物件と紐づいていない限り生産候補から除外する」といった不自然な制約。
- **正当な設計**:
  - 盤面の幾何構造（前線までの距離、開通レーン数、地形狭隘度）やマスターデータ（移動力、燃料、射程）から導出した一般化ルールとして定義する。

### 1.3 異種の価値を雑多に合算するスコアの禁止
- **禁止パターン**:
  - 「ダメージ%」＋「HP」＋「資金G」＋「距離マス」を根拠なく線形結合する（例: `hp * 10 + damage * 5 - dist * 3`）。
- **正当な設計**:
  - **物理尺度による一元化**:
    - **時間（ターン数/ETA）**: 到着ターン、初撃ターン、占領完了ターン。
    - **経済（資金G）**: マスターデータ再調達価格、期待損失額、ターン収入、NPV。
    - **交戦実効性**: 実ダメージチャートに基づく撃破ターン、残HPの資産価値。

## 2. 比較可能な評価値の導入（壁・遅滞・火力）

歩兵（安価な壁・遅滞ユニット）と、戦車・自走砲・装甲車（火力・快速ユニット）を比較する際は、別々の評価体系にせず、同一の指標で比較します。

1. **実戦力維持価値 (`surviving_combat_value`)**:
   - シミュレーション後に生き残る自軍ユニットの再調達価格換算（HP比例）。
   - 安い歩兵は撃破されやすいため生存価値が低く、重装甲・長射程ユニットは損耗しにくいため高い価値を残す。
2. **敵戦力削減価値 (`remaining_enemy_value`)**:
   - 撃破・損耗させた敵ユニットのマスターデータ価格換算。
3. **初撃・接敵ターン (`first_attack_turn` / ETA)**:
   - 快速ユニット（装甲車等）は早いターンに前線へ到達・交戦できるため時間価値で優位に立つ。
4. **占領レーン成立数 (`cleared_capture_lane_count`)**:
   - 占領役が安全に物件へ到達し占領を完了できるか。壁ユニットが前線で敵を引きつけることで、占領役の生存率（レーン成立数）が向上する効果として自然に評価される。

## 3. レビュー観点チェックリスト

改修前に以下の項目を必ず自己点検してください：

- [ ] 新たに追加した定数に、選定理由と較正根拠の日本語コメントがあるか？
- [ ] 同じ意味の定数・ペナルティが複数箇所に重複して分散していないか？（DRY原則）
- [ ] 兵種名（`UnitType::*`）のハードコード分岐を増やしていないか？
- [ ] 変更に対する境界条件・順序関係を保証する単体テスト（Unit Test）が存在するか？
- [ ] `cargo clippy --all-targets --all-features -- -D warnings` に警告なく通過するか？
