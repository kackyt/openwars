## Issue 本文を更新しました（Phase 1 完了・設計方針変更）

Phase 1（評価基盤・baseline 取得・真因分析）の完了に伴い、本文を更新しました。あわせて戦略設計の方針を変更しています。

### 設計方針の変更

当初の「敵本島への単一侵攻目標（`invasion_target`）を改善する」方針を破棄し、全島を毎ターン評価する島嶼キャンペーン・ポートフォリオ方式へ変更しました。理由は以下のとおりです。

1. 島嶼マップで序盤から敵本島へ攻め込むこと自体が不利。敵のいない中立島が多数あり、そちらを先に取るべき。
2. 収入の少ない序盤に装甲車を輸送船（16,500G）で運ぶのはコストが見合わない。輸送ヘリ 4,000G ＋軽歩兵2体 2,000G ＝ 6,000G の低コスト編成で収入基盤を確保するほうが有利。
3. 単一 `invasion_target` では中立島の取り合い、増援、撤退、確保済み島の再防衛を表現できない。

設計書: `docs/superpowers/specs/2026-07-28-issue-58-island-campaign-portfolio-design.md`

### 評価対象の変更: V2 → V1 + 自己対戦

V2 は島嶼侵攻を積極的に行わないため、中立島の取り合い・撤退・増援・確保済み島の再防衛を評価できません。以下へ変更しました。

- 比較評価: V3 対 V1、3マップ × 4 seed × 2手番 = 24試合
- 行動評価: V3 自己対戦、map_3 × 4 seed = 4試合（勝敗ではなく両プレイヤーの行動を個別判定）

既存の V3 対 V2 baseline（`benchmarks/issue-58/baseline-e6e462e.{json,md}`）は診断資料として保存しますが、新設計の比較基準には使用しません。

### 既知制約: プロセス間の決定的再現性は未達

`GameRng` の seed は固定されますが、`engine/src/ai/production.rs:152-193` と `engine/src/ai/production.rs:231-303` が `UnitRegistry` の `HashMap` 反復順をそのまま走査し、同スコア候補を「先に現れた方」で採用します。Rust の `HashMap` 反復順はプロセスごとに変わるため、同一 seed・同一コミットでも生産選択が分岐しえます（map_3 / seed 58001 / V3=P1 の再実行で T1 に「重歩兵」と「軽歩兵」へ分岐することを確認）。

現 baseline の数値は同一プロセス内で取得した実測値です。決定的 tie-break の導入は Phase 2 の受け入れ条件に含めました。
