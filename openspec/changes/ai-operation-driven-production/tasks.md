# Tasks

## 実装方針の確定事項（本文の「V3」読み替え）

本変更は当初 V3 を直接改修する前提で記述されていたが、**実装は `AiVersion::V4` という独立バージョンとして行った**。したがって以下のとおり読み替える:

- 作戦駆動生産の実装先は V4（`engine/src/ai/v4/`）であり、**V1 / V2 / V3 の生産経路は一切変更しない**（`decide_production` 冒頭で V4 のみ委譲）
- 「V3 vs V2 の回帰評価」は「**V4 vs V3 / V4 vs V1 の対戦評価**」に読み替える
- Phase E の「V3 の `ideal_composition` 撤去」は不要になった。V4 は `GamePhase` 別の理想比率補正を通る経路自体を持たないため、撤去ではなく**非採用**という形で目的を達成している。V3 側の `ideal_composition` は現状維持

各 Phase の完了条件は共通して以下を満たすこと:

- `cargo test` が通る
- `cargo clippy --all-targets --all-features -- -D warnings` が通る
- `cargo fmt --all -- --check` が通る
- `scripts/eval_matchup.py` による V4 vs V3 / V4 vs V1 の対戦評価で、勝率が前 Phase 比で有意に低下していない（map_1 / map_2 / map_3）

回帰評価では勝率に加えて以下を計測項目とする（design.md の Risks に対応）:

- 未接敵ターンにおける戦闘ユニット購入額
- 空き生産枠数 × ターン の累計、および最大保有資金
- 自軍の占領数（map_1 / map_2 の現行 V3 はいずれも 0 件）

- [ ] D-1. 予約台帳を保持する Resource を `engine/src/resources/` に追加する（作戦 ID → 予約額・購入済み Entity 群・予約開始ターン・見送り連続ターン数）
- [ ] D-2. 一括編成モードの作戦が必要予算を予約し、他作戦の生産へ回さない制御を実装する
- [ ] D-3. 毎ターンの作戦再構築時に、購入済み Entity を当該作戦の割当として引き継ぐ
- [ ] D-4. 割当戦力を「展開済み / 割当済みかつ未展開」で区別し、`operation_ready` の判定を展開完了条件とする
- [ ] D-5. 割当 Entity が消滅した場合に、当該枠を shortfall へ戻す処理を実装する
- [ ] D-6. 見送り購入を実装する（最優先の未充足枠を埋める候補が買えない場合、安価な候補で当該枠を埋めずに購入を見送る）
- [ ] D-7. 見送りが発生した枠以外の未充足枠に対しては、通常どおり購入を継続することを保証する
- [ ] D-8. `RESERVATION_PATIENCE_TURNS`（既定 5）による完成見込み判定を実装し、見送りの連続ターン数も同じ閾値で管理する
- [ ] D-9. 縮小編成（撃破枠を削り占領要員＋輸送のみで発進）への降格を実装する
- [ ] D-10. 縮小編成でも成立しない場合の予約解除と予算再配分を実装する
- [ ] D-11. 観測量の算出を実装する: 占領レース速度差 / 消耗率（実損失 ÷ 想定損失） / 収入トレンド / 脅威カテゴリ別の敵戦力と所在地 / 枠の充足 / 自軍拠点への奪還脅威 / 空き枠と資金の乖離
- [ ] D-12. 観測量に基づく作戦の生死判定を実装する（占領劣勢 → 撃破枠を占領・輸送枠へ振替 / 消耗率超過 → 護衛上積み → 縮小 → 中止 / 充足枠の解放）
- [ ] D-13. 自軍拠点が敵占領ユニットの脅威下に入ったことを検知し、`priority_rank = 0` の防衛作戦を生成する処理を実装する（同時生成数に上限を設ける）
- [ ] D-14. `priority_rank = 0` の防衛作戦による予約 preempt を実装する
- [ ] D-15. `squad.rs` の発進判定と接続し、パッケージ完成時に部隊が発進することを確認する
- [ ] D-16. ユニットテスト: 部分購入済みパッケージがターンをまたいで保持され、不足分のみ再要求されること
- [ ] D-17. ユニットテスト: 輸送中の割当戦力が「充足」と誤判定されないこと
- [ ] D-18. ユニットテスト: 割当 Entity 消滅時に shortfall が復活すること
- [ ] D-19. ユニットテスト: 資金が最優先候補の価格にわずかに届かないとき、安価な候補で枠を埋めずに見送ること
- [ ] D-20. ユニットテスト: 見送りが規定ターン数連続したときに降格経路へ乗ること
- [ ] D-21. ユニットテスト: 完成見込みなし判定で縮小編成 → 予約解除の順に降格すること
- [ ] D-22. ユニットテスト: 自軍拠点が脅威下に入ったとき防衛作戦が生成され、攻勢作戦の予約を preempt できること
- [ ] D-23. ユニットテスト: 占領レース速度差が負に大きいとき、撃破枠の要求が減り占領枠・輸送枠へ配分が移ること
- [ ] D-24. ユニットテスト: 空き枠が残り資金が積み上がっている状況で、占領要員の補充要求が必ず生成されること
- [ ] D-25. 回帰評価を実行し、予算滞留（長期にわたる生産ゼロ、空き枠 × ターンの累計、最大保有資金）が改善していることをログで確認する
- [ ] D-26. 回帰評価で攻勢作戦の発進回数が Phase C から減っていないことを確認する（防衛作戦の乱立による攻勢阻害のチェック）
